# 大瓜生山祭 物販ナビ（非公式）

大瓜生山祭の有志物販に出展するサークル・作家の**お品書きをまとめたWebカタログ**です。
スマホで、会場の地図と出展者の一覧を見ながら、お目当てのスペースを探せます。

> 運営：KUA StuHUB（非公式）— 通信・通学を問わない学生の有志団体。問い合わせ：kua.stuhub@gmail.com
> 有志による非公式の取り組みです。大学・学園祭実行委員会・物販イベント主催とは関係ありません。

## しくみ

```
出展者 ──投稿──▶ Tally（掲載フォーム）
                    │ 自動
                    ▼
運用担当 ──確認──▶ Notion「出展者」データベース（審査ボードで「公開」へ）
                    │ 15分ごとに自動で読み込み
                    ▼
               GitHub Actions（サイトを作る・画像を圧縮する）
                    │
                    ▼
               GitHub Pages（公開中のサイト）──▶ 来場者のスマホ
```

- 運用担当が触るのは **Notion だけ** です。コードを触る必要はありません。
- サイトに出るのは「審査」が **公開** の出展者だけです。
- 「連絡先（非公開）」の列は読み込まないので、サイトには出ません。
- Notion と連携するまでは、**ダミーデータ**で動きます（画面上部に「試運転中」と出ます）。

## はじめての公開（GitHub Pages）

所要時間は10〜15分です。お金はかかりません。

1. **GitHub のアカウントを作る**：https://github.com/signup
2. **リポジトリ（置き場所）を作る**：右上の「＋」→「New repository」
   - Repository name：`butsuhan-navi`（URLの一部になります）
   - **Public** を選ぶ（無料で公開するため。Notionのキーなど秘密の情報はここには入りません）
   - 「Create repository」
3. **ファイルを入れる**：「uploading an existing file」から、このフォルダの中身をすべてドラッグ＆ドロップ →「Commit changes」
   - ⚠ `.github` フォルダは隠しフォルダなので、Mac の Finder では見えないことがあります。見えないときは「Add file」→「Create new file」で、ファイル名に `.github/workflows/deploy.yml` と入力し、中身を貼り付けて保存してください。
4. **公開をオンにする**：「Settings」→ 左の「Pages」→「Build and deployment」の Source を **GitHub Actions** にする
5. **初回の更新を走らせる**：「Actions」タブ →「サイトを更新」→「Run workflow」
   - 1〜2分で緑のチェックになります。
6. サイトの URL は **`https://kua-stuhub.github.io/butsuhan-navi/`** です。

## 本番データに切り替える（Notion 連携）

1. **連携用のキーを作る**：https://www.notion.so/profile/integrations →「新しいインテグレーション」
   - 名前：`物販ナビ`、種類：内部（Internal）
   - 「機能」は **コンテンツを読み取る** だけにチェック（書き込みは不要）
   - 作成後に表示される「シークレット」（`ntn_` で始まる文字列）をコピー
2. **データベースに招待する**：Notion で「大瓜生山祭 物販ナビ（非公式）」ページを開く → 右上「•••」→「接続」→ `物販ナビ` を追加
3. **GitHub にキーを登録する**：リポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」
   - Name：`NOTION_TOKEN`
   - Secret：コピーしたシークレット
4. 「Actions」→「サイトを更新」→「Run workflow」。上部の「試運転中」の帯が消えれば本番データです。

> ⚠ シークレットはパスワードと同じです。ファイルに書いたり、SNSやチャットに貼ったりしないでください。漏れたら Notion の画面で「再発行」すれば古いものは使えなくなります。

## 毎日の運用

### 新しい投稿が来たら
1. Notion の「出展者」を開く
2. **番号チェック**（⚠ が一番上に出る）と **重複チェック（名前）** をざっと見る
   - 同じサークルの申請が2件 → 古い方を「非公開」に
   - 番号が ⚠ → 出展者に確認して「全件」タブでスペース番号を直す
3. **審査ボード**で画像と文章を確認する（いたずら・不適切な内容でないか）
4. 問題なければカードを **「公開」へドラッグ**。迷うものは「保留」へ
5. 15分ほどで自動的にサイトに出ます。急ぐときは GitHub の「Actions」→「サイトを更新」→「Run workflow」

### 修正・削除の依頼が来たら
- 依頼者が本人かどうかを、Notion の「連絡先（非公開）」と照らし合わせて確認する
- 修正：Notion の内容を直す（画像の差し替えも Notion で）
- 削除：「審査」を「非公開」にする（行は消さなくてよい）
- どちらも15分ほどで反映されます

### 当日
- 売り切れなどの連絡は「ひとことコメント」を書き換えて反映できます
- 反映を急ぐときは手動で「Run workflow」

## 共有ボタンとプレビュー画像

出展者の詳細にある「共有」（PC では「リンクをコピー」「Xでポスト」）で、その出展者のページを共有できます。

- 共有されるのは `https://…/butsuhan-navi/e/<ID>/` という出展者ごとのページです。開くと、サイト本体でその出展者の詳細と地図が開きます
- X や LINE などに貼ると、**地図カード**（左にスペース番号・部屋・サークル名・頒布物、右にそのブースを朱色にした会場図）がプレビューに出ます。お品書き画像は使いません
- 地図カードは15分ごとの更新のときに自動で作られます。サークル名・スペース番号・頒布物・配置図を直すと作り直されます
- サークル名が長いときは、文字を小さくして最大4行まで。入りきらない分は「…」になります
- 「非公開」にすると次の更新で出展者のページは消えますが、X などは一度作ったプレビューをしばらく残します。削除依頼にはそのことも伝えてください
- 独自ドメインにしたら、`config.json` の `site.url` を新しいURLに書き換えます（空にするとプレビュー画像は作られません）

## アクセス解析（Cloudflare）

同意した来場者だけ、どの出展者の詳細・写真が何回開かれたか、お気に入り・共有の回数などを数えます。数字は運営の中だけで見て、各出展者には自分の分だけを渡します（順位は出しません）。

- 数えた回数はスマホの中にためておき、画面を閉じたとき（ホーム画面に戻る・アプリの切り替えなども含む）に、前回から30分以上たっていればまとめて送ります
- 名前・連絡先・位置情報・検索した言葉・端末を見分ける番号は送りません。IP アドレスも保存しません
- `config.json` の `analytics.endpoint` が空のあいだは、計測も同意のお知らせも出ません
- 同意のお知らせはサイトをはじめて開いたときに出ます。「？」から同意の変更と「データの取り扱いについて」（規約）が見られます。規約の文は `src/app.js` の `POLICY`

### 設定のしかた（初回だけ・15分）
`kua.stuhub@gmail.com` で https://dash.cloudflare.com/sign-up からアカウントを作り（無料）、画面で次のように進めます。画面の名前は変わることがあります。

1. **データベースを作る**：左の「Storage & Databases」→「D1」→「Create」。名前は `butsuhan-analytics`
2. **表を作る**：できたデータベースの「Console」に次の1行を貼って「Execute」（`worker/schema.sql` を丸ごと貼ると、改行が消えて全部コメント扱いになり「No SQL statements detected」と出る）
   ```
   CREATE TABLE IF NOT EXISTS batches (at TEXT NOT NULL, data TEXT NOT NULL);
   ```
3. **受け取り口を作る**：左の「Workers & Pages」→「Create」→「Start with Hello World!」。名前は `butsuhan-analytics` →「Deploy」→「Edit code」で中身を消して `worker/analytics.js` を貼り付け →「Deploy」
4. **データベースをつなぐ**：その Worker の「Settings」→「Bindings」→「Add」→「D1 database」。Variable name は `DB`、データベースは 1 で作ったもの
5. **設定値を入れる**：「Settings」→「Variables and Secrets」→「Add」
   - `SITE_ORIGIN`（Text）：`https://kua-stuhub.github.io`
   - `EXPORT_TOKEN`（Secret）：集計を取り出すときの合言葉（長めの英数字。共有パスワード管理アプリに保存）
6. Worker の URL（`https://butsuhan-analytics.〇〇.workers.dev`）をコピーして、`config.json` の `analytics.endpoint` に書いて push

> ⚠ EXPORT_TOKEN はパスワードと同じです。コードやチャットに書かないでください。

### 集計を見る
1. ブラウザで `<Workers のURL>/export?token=<EXPORT_TOKEN>` を開くと、合計の数字が出ます。`export.json` として保存
2. 公開サイトの `data.json` を保存して `node tools/analytics-report.mjs export.json data.json > report.csv` を実行すると、出展者ごとの表になります

### 無料枠
Workers は1日10万リクエスト、D1 は1日10万行の書き込みまで無料です（日本時間の朝9時に戻る）。1回の送信が1リクエスト・1行なので、1.5万人が同意しても1日数万件の見込みです。超えた場合はその日の送信が失敗するだけで、サイトは普通に見られ、数字はスマホに残って次の機会に送られます。

### イベントが終わったら
- `report.csv` を作って出展者に渡したら、2026年12月31日までに D1 の `batches` を削除する（規約で約束している）。合計の数字は StuArchive の記録に残す
- 来年も使うなら Worker はそのまま。使わないなら `analytics.endpoint` を空にする

## 配置図を直す・作る（配置図エディタ）

`tools/map-editor.html` をダブルクリックして、PC のブラウザで開きます（ネットには何も送りません）。

1. **今の配置図を直す**：「開く」で `data/layout.json` を選ぶ
   **新しく作る**：「画像から新しく作る」で配置図の画像（PNG / JPG）を選ぶ。PDF は先に画像にする
2. 今の配置図に下絵を重ねたいときは「下絵を読み込む」。濃さはスライダーで調整
3. 左の道具で描く
   - **部屋（R）**：ドラッグで描いて、右側で名前（例：NA410）を入れる
   - **スペース（B）**：1つずつ描く。番号は自動で次の番号になる
   - **並べて描く（S）**：机の列をまとめてドラッグ → 個数と最初の番号を入れると等分して並ぶ
   - **選択（V）**：押して選ぶ・ドラッグで移動・角の□で大きさ変更。空いた所をドラッグで範囲選択。複数選んで「この順で番号を振る」で連番の振り直し
4. 右の「チェック」に、番号の重複・部屋の外のスペース・重なり・抜けている番号が出ます。押すとその場所に移動します
5. 「立体で確認」で、サイトと同じ見え方を確認
6. 「書き出す」で `layout.json` がダウンロードされる → `data/layout.json` に上書きして push

- 作業中の内容はブラウザに自動で下書き保存されます（次に開いたとき「前回の作業の続きから」）
- 番号の最大が変わったら、Notion の「照合：番号」の数式の最大番号も書き換える（2026年は `90`。エディタの「全体」欄に出ます）。数式は「15　アニクエ」のような先頭の番号を読みます
- 2026年の `data/layout.json` は、配置図の画像のピクセルを1.6倍した座標です（机を2025年と同じくらいの大きさにして、立体表示がごちゃつかないようにするため）。エディタで下絵を重ねるときは、画像を1.6倍に拡大してから読み込んでください
- 壁（`walls`）は配置図の紺の線を `[x1, y1, x2, y2]` で並べたものです。`walls` があると、部屋と通路を1つのフロアとして描き、部屋ごとの箱の壁は描きません
- 通路（`paths`）は床だけ描く範囲です。壁と通路はエディタでは編集できないので、変えるときは `data/layout.json` を直接書き換えます（エディタで開いて書き出しても消えません）
- 番号が数字でないスペース（「受付」「フォトブース」など）は、サイトでは押せない青い目印になります
- サイトを作るときに、出展者のスペース番号が配置図にないと Actions のログに ⚠ が出ます

## 配置図の出展者リスト（data/roster.json）

配置図の青枠に載っている「番号・名前」を書き起こしたものです。

- お品書きが未掲載のスペースを押すと、ここの名前が「配置図より」として出ます。検索でも一覧の下に出ます
- 画像から読み取れなかった文字は `〓`、確認が必要なものには `check` が付いています。**`check` が付いている・`〓` が入っている名前はサイトに出ません**。確認できたら `name` を直して `check` を消してください
- 投稿の名前が、同じ番号の配置図の名前と違うときは、Actions のログに ⚠ が出ます（番号の書き間違いの発見用）
- 掲載フォームの「スペース番号・サークル名」は、このリストから作ったプルダウンです（例：`15　アニクエ`）。番号や名前を打つと絞り込めます。Notion の「スペース番号」列にはこの形のまま入り、サイトを作るときに番号と名前に分けます
- サークル名の欄は任意です。空欄ならプルダウンで選んだ名前で掲載し、入力があればそちらを使います
- 名前を直したら `npm run form-options` で選択肢を出し直し、Tally のプルダウンの選択肢を貼り替えて公開する

## 年に一度やること
- `config.json` の `event`（年・日程・説明文）を書き換える
- 配置図が変わったら、配置図エディタで `data/layout.json` を作り直す（上の「配置図を直す・作る」）
- Tally のフォームと Notion のデータベースは、前年のものを複製して使う。データベースが変わったら `config.json` の `notion.databaseId` も書き換える

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 「Actions」に赤い ✕ が出ている | ✕ をクリック →「サイトを作る」のログを見る。Notionのキーが間違っている・期限切れのことが多い |
| 「公開」にしたのに出てこない | 15分待つ／手動で Run workflow。ログに ⚠ が出ていないか確認 |
| 画像が出ない出展者がいる | ログの ⚠ に理由が出ます。HEIC形式などは変換できないので、JPEG/PNGで送り直してもらう |
| スペースが地図で光らない | スペース番号の表記が配置図と合っているか（例：「12」と「A-12」） |
| 15分ごとの自動更新が止まった | GitHubは60日間変更がないと自動更新を止めます。Actions で「Enable workflow」を押す |

## 開発メモ

```sh
node scripts/build.mjs             # NOTION_TOKEN があれば本番データ、なければダミー
USE_SAMPLE=1 node scripts/build.mjs  # ダミーで作る
npm run preview                    # http://localhost:8080 で dist/ を確認
```

- 依存は画像圧縮の `sharp` と、プレビュー画像の文字を描く `opentype.js`（どちらも無くても動くが、画像の圧縮・プレビュー画像の作成はされない）
- 画面に出す文字はすべて `esc()` を通す。SNSリンクは `http(s)` だけ許可
- 出展者の表示順は閲覧者ごとのシャッフル（`localStorage` の乱数シード）で、特定の出展者を優遇しない
